# Ключи и доступы: что вписать в .env при установке

Здесь записано, **кто админ** и **какие ключи нужны**, но не сами ключи.
Значения в репозиторий не кладутся никогда: репозиторий копируют, клонируют
и показывают, а ключ, однажды попавший в историю git, оттуда уже не убрать.
Ключ Resend, найденный в открытом коде, его сканер ещё и отзывает сам.

Значения хранятся у владельца (менеджер паролей) и вписываются руками в
`/srv/luckybox/.env` на сервере. Установщик `deploy/install.sh` создаёт этот
файл из `.env.example` и в конце напоминает, что заполнить.

## Что вписать в .env

| Переменная | Что это | Где взять | Состояние |
|---|---|---|---|
| `SITE_URL` | Адрес сайта с https | Ваш домен | Установщик впишет сам |
| `PAYOUT_DATA_KEY` | Шифрование номеров карт | Установщик создаёт сам | **Не менять никогда** |
| `RESEND_API_KEY` | Письма: сброс пароля | resend.com -> API Keys, доступ Sending | Ключ выдан, проверен |
| `MAIL_FROM` | Отправитель писем | Адрес на подтверждённом в Resend домене | Пока `onboarding@resend.dev` |
| `DATABETRIX_AGENT_NAME`, `DATABETRIX_AGENT_TOKEN` | Казино: запуск игр | Кабинет агрегатора, профиль агента | Нужно взять в кабинете |
| `SICILIA_MERCHANT`, `SICILIA_LOGIN`, `SICILIA_API_KEY` | СБП и карта | merchant.sicilia.ink -> API | Нужно взять в кабинете |
| `SICILIA_PAY_URL` | Адрес платёжного окна | Поддержка Sicilia | `https://payment.sicilia.ink`, уже в `.env.example`. Не нужен: реквизит показывает касса (`SICILIA_PAYIN=h2h`) |
| `SICILIA_CALLBACK_IPS` | Адрес шлюза для колбэков | Поддержка Sicilia | `91.206.228.46`, уже в `.env.example` |
| `HELEKET_MERCHANT`, `HELEKET_API_KEY` | Криптокасса | Кабинет Heleket | По желанию |
| `OPS_BOT_TOKEN` | Служебный бот: оповещения о сбоях и вход в панель | @BotFather, бот **@luckyspec_bot** | Токен выдан и проверен, хранится у владельца |
| `OPS_OWNER_CHAT_ID` | Telegram главного админа для подтверждения входа | Уже стоит в `.env.example`: **8602356502** | Готово |
| `OPS_ALERT_CHAT_ID` | Общий чат команды для оповещений | id группы, см. `.env.example` | По желанию |
| `TELEGRAM_TOKEN`, `TELEGRAM_BOT_USERNAME` | Вход через Telegram, игровой бот | @BotFather, второй бот | По желанию |
| `TG_CHANNEL_ID`, `TG_CHANNEL_URL`, `FREE_CASE_ID` | Кейс за подписку на канал | Ваш канал, игровой бот в нём админом | По желанию |
| `RCLONE_REMOTE` | Куда отправлять копии базы с сервера | rclone config, любое облако | Нужен до запуска |

Остальные переменные `.env.example` - пороги и сроки с разумными значениями
по умолчанию, у каждой там объяснение. Трогать их для запуска не нужно.

**Ботов в проекте два, и это разные боты.** Служебный (`OPS_BOT_TOKEN`) пишет
только команде: сбои и подтверждение входа в панель. Игровой
(`TELEGRAM_TOKEN`) - игрокам: вход через Telegram, напоминания, канал. Один
токен на оба нельзя: обновления служебного бота читает сервер, а два
читателя на одном токене Telegram не пускает.

Логины и пароли от кабинетов (Databetrix, Sicilia, Heleket) в `.env` не
нужны вовсе: сервер ходит в API ключами, а не паролями кабинетов. Храните их
только в менеджере паролей.

## Resend: что осталось сделать

1. **Подтвердить домен** в resend.com/domains: добавить домен (лучше
   поддомен, например `mail.ваш-домен.ru`) и внести у регистратора DNS-записи,
   которые покажет Resend. Пока этого нет, письма уходят только на почту
   владельца аккаунта Resend, а игрокам не доходят.
2. После подтверждения поменять `MAIL_FROM` на адрес этого домена, например
   `LUCKYBOX <no-reply@mail.ваш-домен.ru>`.
3. Ключ, отправленный в чат, после запуска заменить новым: в чате он уже
   лежит открыто.

## Ключи, которые уже светились в переписке

Всё, что пересылалось в чат открытым текстом (пароли кабинетов, ключ Resend),
перед запуском на живых деньгах замените: смените пароли кабинетов,
перевыпустите ключи API и впишите новые значения в `.env` на сервере.
