## 0. Одной командой

Всё из разделов 1-3 делает один скрипт (`deploy/bootstrap.sh`): спрашивает
домен и ключи, направляет DuckDNS, ставит брандмауэр, проект, сертификат,
вписывает ключи, запускает и проверяет сайт снаружи. Сбой на любом шаге
возвращает сервер как было, база не трогается. Повторный запуск безопасен.

    bash <(curl -fsSL https://raw.githubusercontent.com/danielyanspace-coder/casssss/claude/github-text-document-aja1hm/deploy/bootstrap.sh)

Ниже - те же шаги по отдельности.

## 1. Сервер и домен

  Хостинг должен разрешать азартные игры в правилах - иначе блокировка без

## 3. Первый старт

- [ ] **Claude.** `sudo systemctl start luckybox luckybox-bot` и таймеры
  `luckybox-backup.timer`, `luckybox-watchdog.timer`. Проверить
  `curl https://домен/api/health`.
- [ ] **Вы, сразу после старта.** Зарегистрироваться на сайте почтой главного
  админа и открыть «Админ»: в Telegram 8602356502 придёт запрос с кнопкой «Это
  я». Привязывать ничего не нужно - Telegram владельца закреплён в `.env`, и
  чужой к нему не привязать. Остальные сотрудники привязывают свой кнопкой в
  панели. **Почта владельца даёт права только при заданных `OPS_BOT_TOKEN` и
  `OPS_OWNER_CHAT_ID`**: почту на сайте никто не подтверждает, и без бота
  владельцем стал бы тот, кто первым её зарегистрирует. Без бота владельца
  задают через `ADMIN_TG_IDS`.
- [ ] **Claude.** `sudo systemctl stop luckybox`, подождать три минуты: в бот
  должно прийти «Сервер не отвечает», после запуска - «Восстановлено». Так
  проверяется, что оповещения действительно дойдут.

## 4. Живые проверки на маленьких суммах

Всё ниже до сих пор проверялось только с подменой сети. Первые настоящие
платежи - на минимальные суммы.

- [ ] Пополнение через Sicilia (СБП и на карту): касса показывает реквизит,

- [ ] Пополнение криптовалютой: счёт создаётся, после оплаты зачисляется.
- [ ] Вывод по СБП: заявка, подтверждение в панели, выплата через Sicilia
  вторым нажатием, заявка закрывается с чеком.
- [ ] Казино: игра запускается, ставка списывает, выигрыш начисляет, баланс в
  шапке сходится.
- [ ] Сброс пароля: письмо приходит на обычную почту игрока.
- [ ] Вход через Telegram (если включён).

### Приёмка Sicilia: 4 сделки на вход, 4 на выход

Шлюз проводит её сам после развёртывания. Перед началом: в кабинете Sicilia
указан колбэк `https://домен/api/webhooks/sicilia` (и для выплат, у них он
статический), IP сервера у них в белом списке, `SITE_URL` задан. Всё видно
в панели: Финансы -> Пополнения и Финансы -> Выводы, номера наши и шлюза
копируются нажатием, их и называйте Sicilia.

На вход (игрок пополняет через окно на 100-500 ₽):
- [ ] 1. Подтверждение: деньги зачислены, статус «зачислен».
- [ ] 2. Подтверждение с изменённой суммой: зачислена сумма шлюза (FactSum),
  в строке «зачислено N ₽».
- [ ] 3. Отмена со стороны Sicilia: статус «отменён шлюзом», денег нет,
  у игрока оплата в «Оплатах в ожидании» с кнопкой «Деньги не пришли».
- [ ] 4. Отмена с нашей стороны: в Пополнениях у оплаты «Отменить у шлюза»
  (два нажатия). Статус «отозван».

На выход (заявка игрока на вывод по СБП, «Выплатить через Sicilia»):
- [ ] 1. Подтверждение: заявка «Выплачено» со ссылкой на чек.
- [ ] 2. Неполное подтверждение: заявка закрыта выплаченной суммой («N из M»),
  остаток сам вернулся игроку на баланс.
- [ ] 3. Отмена со стороны Sicilia (возврат в общий пул): заявка остаётся «в
  работе», бот сообщает об отмене. Дальше снова «Выплатить через Sicilia» или «Вернуть в
  ожидание» и отклонить с возвратом.
- [ ] 4. Отмена с нашей стороны: «Отозвать из Sicilia», пока трейдер не взял
  выплату. Заявка снова «ожидает».

Если колбэк не дошёл, ничего не теряется: сверка раз в 5 минут спрашивает
статус сама. Ускорить можно кнопкой «Проверить у шлюза».

## 4а. Партнёрка и финотдел

- [ ] **Вы.** Вписать условия Sicilia в кабинете `https://домен/partners/` ->
  Настройки: комиссия на приём, на выплату и фикс за выплату. Без них долг
  шлюза считается без комиссий.
- [ ] **Вы.** Там же решить условия партнёров: доля по умолчанию (50%),
  процент и потолок бонуса по коду, минимальный вывод, доля агрегатора с
  дохода казино (её вычитают до доли партнёра).
- [ ] **Вы.** Каждый перевод от Sicilia вам вносить в Финансы -> Расчёты с
  Sicilia: иначе долг шлюза будет расти на бумаге.

## Смена домена

`sudo luckybox-domain новый-домен.duckdns.org` - сертификат, nginx, SITE_URL,
перезапуск; старый домен переадресует на новый. Для DuckDNS впишите
`DUCKDNS_TOKEN` в `.env` и заведите новый поддомен на duckdns.org заранее.
После смены поменяйте адреса в кабинетах Sicilia, Databetrix, Heleket и
`/setdomain` у бота: скрипт печатает их списком.

## Что продолжит работать без вас

- **Сторож** раз в минуту: сервер, сайт снаружи, сертификат, диск, свежесть
  копий. Сбой - сообщение в служебный бот, починка - «восстановлено».
- **Сервер сам** сообщает: падение процесса, частые ошибки 500, отказы и
  недоступность Sicilia и Heleket, пустой баланс агента казино, ошибки
  кошелька казино, несработавшую синхронизацию каталога, неотправленное письмо.
- **Копия базы** раз в час, со сжатием и проверкой целостности; не сделалась
  или не уехала в облако - сообщение.

Чего сторож не увидит: если умрёт сам сервер целиком, сообщать будет некому.
Для этого нужен внешний монитор (UptimeRobot или аналог) на
`https://домен/api/health` - бесплатно, пять минут настройки.
