# Первый вход: оптимизация 29 октября 2026

Изменения подготовлены на основе текущих файлов `/srv/luckybox` (HEAD 5030876),
с сохранением существующих незакоммиченных правок казино и автономной сборки.
На рабочий сайт этот набор пока не установлен.

## Что изменилось

- `boot.js` выполняется асинхронно из head и начинает запросы конфига и игрока,
  пока загружается граф приложения. Личных данных нет в localStorage или HTTP-кеше.
- Обязательный статический импорт 41 темы заменён загрузкой выбранных тем.
  `openCase` дожидается всех рисунков состава и витрины. На это время виден
  существующий загрузчик; при ошибке открытия нет, можно повторить запрос.
- Уход из раздела отменяет отложенное открытие. Старый ответ не открывает кейс
  поверх новой страницы и не прячет загрузчик другого открытия.
- Лента ждёт рисунков своих предметов. Боковое меню работает сразу: рисунок
  приза подгружается отдельно в рамку с прежним размером.
- Остальные темы начинают загружаться через 2,5 секунды после запуска, по одной,
  с паузой 350 мс. Фон приостанавливается для открытого/загружающегося кейса
  и скрытой вкладки, отключается при экономии трафика.
- Рулетка, апгрейд и экран проверки честности готовят скрытую разметку при входе
  в свой раздел. У главного баннера высокий приоритет загрузки.
- URL основного скрипта имеет новую версию, чтобы новый HTML не использовал
  старый кеш app.js. Уже закешированный старый HTML обновится при перезагрузке
  с проверкой кеша или по истечении его текущего срока хранения.
- В автономном HTML темы по-прежнему встроены: сетевые импорты для него не нужны.

## Проверено

- `npm run test:modules`: синтаксис и импорты 60 модулей.
- `npm run test:art`: 89 проверок исходного набора рисунков.
- `npm run test:startup`: 842 SVG нового загрузчика совпадают с исходными
  (без уникальных идентификаторов градиентов); запросы объединяются, повтор
  после сетевого отказа меняет URL модуля, отмена и повтор открытия безопасны;
  фон уступает выбранному кейсу; стартовые API запускаются параллельно,
  401 корректно означает гостя; скрипт из настоящего шаблона демо разбирается.
- `npm run verify`: математические проверки завершились успешно.
- 45 файлов рисунков и стилей побайтно совпадают с рабочим сайтом.
- `git diff --check`.

Полная сборка демо с пережатием картинок, браузерные тесты, сравнение снимков
и время первого/повторного входа здесь не проверены: Chromium блокируется
песочницей, DNS домена недоступен. Эти ограничения не дают утверждать,
что задержка живого сайта уже устранена или что визуальная регрессия исключена.

Для доступной среды подготовлен браузерный замер:

```bash
npm run measure:startup -- https://lucky-box.duckdns.org /tmp/startup-before
# После установки изменений:
npm run measure:startup -- https://lucky-box.duckdns.org /tmp/startup-after
```

Он делает по три открытия без HTTP-кеша и повторно для компьютера и телефона
(для телефона: 3 Мбит/с, задержка 120 мс, CPU x4). Сохраняет JSON с TTFB,
моментом готовности полок, ресурсами, ошибками и снимки первого прогона.
LCP/long tasks в JSON фиксируются на момент готовности полок, а не за весь
срок жизни страницы. DNS/TLS зависят от реального расположения раннера;
повторяемые прогоны не считаются отдельными замерами холодного DNS.

## Установка

`startup-optimization.patch` содержит только новые изменения относительно
текущих файлов сайта. В него не включены уже существующие правки казино,
секреты, база и зависимости. Перед применением:

```bash
git -c safe.directory=/srv/luckybox -C /srv/luckybox apply --check /root/luckybox-startup/startup-optimization.patch
```

Рабочая среда этой задачи допускает запись только в `/root` и `/tmp`.
Применение к `/srv/luckybox`, проверка через браузер и повторный сетевой замер
остаются обязательными шагами перед объявлением результата на живом сайте.
