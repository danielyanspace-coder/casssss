## Измерения и исправления

Локальный Chromium, экран 390×844, CPU замедлен в 4 раза. Три запуска,
по пять обновлений баланса в каждом. Это сравнение операций в тестовой среде,
а не обещание времени отклика для любой сети и любого телефона.

| Операция | До | После | Изменение |
|---|---:|---:|---|
| Обновление баланса в клиенте | около 30–55 мс | обычно 1–4 мс | Полки и меню сохраняются, обновляются только зависимые элементы |
| `/api/config`, локальная медиана | 9,9 мс | 6,5 мс | Сериализация публичных кейсов вынесена из каждого запроса; динамические настройки сверяются сразу |
| Повторные запросы публичного лобби | 60,5 мс | 7,8 мс | Кеш на секунду; запросы без записей DEV_MODE |

Полный старт и открытие кейса дополнительно профилируются, но их абсолютные
замеры зависят от параллельных тестов, декодирования картинок и нагрузки
машины, поэтому ускорение для них в процентах не заявляется.

Сборка лобби на каталоге около 5 000 игр занимала примерно 190 мс. Добавлен
кеш публичных блоков на секунду с немедленным сбросом при любых записях
через текущее SQLite-соединение и при коммитах внешнего соединения. Такой
консервативный сброс сохраняет актуальность обложек и результатов; при частых
записях доля попаданий в кеш будет ниже.

Другие исправления:

- ограниченный кеш SVG-шаблонов с уникальными ссылками каждой вставки;
- сохранение введённого промокода и DOM при фоновых обновлениях;
- отмена незавершённых обложек при уходе, смене экрана и пагинации казино;
- отдельные таймауты обложек вместо ожидания до 40 секунд × 4 попытки;
- временный отказ CDN (429/таймаут) не превращается в постоянное отсутствие;
- отсутствие перекрывающихся фоновых запросов баланса и витрины;
- регистрация гостя из казино открывается сразу, без запроса запуска игры;
- параллельные открытия кассы используют один запрос настроек каждого шлюза;
- памятка бонуса оформлена тремя раскрывающимися шагами и сохраняет своё состояние;
- случайная проверка доли крупных выпадений исправлена под текущий контракт:
  заявленная доля относится к синтетической части, а не к реальным раундам.

## Повторение проверок

Используйте Node.js 20, как в CI. Для локального сервера нужна отдельная
тестовая база; DEV_MODE не включают на рабочем сервере.

```bash
PORT=3100 DB_PATH=/tmp/luckybox-audit/app.db ADMIN_TG_IDS=999000001 npm run dev
npm run perf:audit -- http://localhost:3100 /tmp/luckybox-perf.json
node test/api.mjs http://localhost:3100
CHROMIUM_PATH=/usr/bin/chromium node test/ui.mjs http://localhost:3100
node test/startup-ui.mjs http://localhost:3100
node test/cashier-ui.mjs http://localhost:3100
node test/performance-ui.mjs http://localhost:3100
npm run test:art
npm run test:casino
npm run test:casino-covers
```

API готовит данные для полного UI-теста; каждый повтор этого прогона требует
свежей базы. В окружении без доступа к CDN изображения провайдеров не могут
считаться проверенными по сети; целевые проверки отмены загрузок используют
свой настоящий медленный HTTP-сервер. Проверки денег используют изолированные
базы и контролируемые ответы шлюзов.
