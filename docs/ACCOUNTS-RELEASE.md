# Счета, получение выигрышей и финансы, 30.10.2026

Основная ветка: claude/github-text-document-aja1hm. Это изменение заменяет
описанные ранее автоматическое смешивание счетов и потолок перевода бонусов.

- users.active_wallet по умолчанию real. chargeBet списывает только выбранный
  счёт. Ставка не добирает недостающие деньги с другого счёта.
- Казино закрепляет счёт в playerId: lb<ID> для основного, lb<ID>b для бонусного.
  Поздние выплаты и откаты используют исходный счёт. Копейки бонусного казино
  хранятся отдельно в bonus_kop, суммы считаются целыми копейками.
- После полного отыгрыша весь бонусный остаток переводится в основные деньги.
  У новых bonus_events convert cashout_pct=-1 означает правило без потолка.
  Исторические переводы проверяются по прежнему правилу.
- pending_rewards держит выигрыш кейса, серии и риска до получения.
  В одной транзакции деньги записываются в историю раунда и убираются из
  доступного остатка. Журнал содержит связанные reward_hold/reward_claim.
  Получение помечает запись и возвращает сумму ровно один раз.
  Ожидающий выигрыш можно получить также из шторки счетов после перезагрузки.
- Новая ставка серии/повторного открытия получает прошлый выигрыш внутри
  транзакции. Интерфейс получает его до проверки доступности кнопки «Ещё раз».
  Автооткрытие получает выигрыш после каждого показанного прокрута.
- Выигрыш бесплатного кейса идёт в основные деньги и withdraw_gift. Эта часть
  доступна без отыгрыша депозита, с сохранением общих минимума и шага вывода.
- Риск не создаёт второй выплаты: сначала получает отложенную ставку, затем
  списывает её, а результат снова откладывает до «Продолжить».
  Отказ от бонуса недоступен, пока его выигрыш ожидает получения.
- Каждая новая строка кейса содержит meta.table с SHA-256 неизменной таблицы
  case_tables. Историческая таблица взята из a96c1dc^; переход рабочего сайта
  на RTP 80% установлен по /srv/luckybox reflog: 28.10.2026 14:18:23 UTC.
  Это время установки именно данного сайта, а не время создания коммита.
  Проверка на копии рабочей базы: все 220 раундов совпали, источники сходятся.
- «Пополнения Сицилии» считает подтверждённые payin и admin_sicilia_disputes
  в окне [from,to). UI принимает даты/часы/минуты МСК. Границы комиссии:
  сумма <=5000:20%, <=10000:18%, выше:15%; mk:26%. Отчёт применяет указанную
  пользователем сетку и к историческим платежам. Настоящий учёт расчётов
  шлюза сохраняет зафиксированные в сделках комиссии.
- История запросов показывает также незавершённые платежи Сицилии и крипто.
  ID пользователя уже является постоянным users.id: его показывают профиль,
  обе панели «Игроки» и поиск по ID (в том числе с #).

Проверки: test/accounts-rewards.mjs, test/accounts-ui.mjs, обновлённые

В ограниченном окружении запрещены listen и запуск браузера, поэтому HTTP,

## Запуск пакета на рабочем сервере

`sudo bash /root/luckybox-accounts-start.sh` запускает службу systemd, SSH
можно закрыть. `sudo bash /root/luckybox-accounts-status.sh` показывает статус
и последние строки журнала в любой момент, в том числе через 20-30 минут.
Полный журнал: `/root/luckybox-accounts-job/output.log`.
Повторный запуск уже установленного пакета ничего не меняет.
Блокировка общая с предыдущими установщиками проекта.
Пакет не скачивает исходники с GitHub: он импортирует проверенный локальный
коммит в основную ветку сайта. Чужой коммит или изменённый файл останавливает
установку до любых правок. Перед применением включается обслуживание,
останавливаются службы, после проверки HTTP возвращается прежний режим.

Выход из кейса (назад, закрытие или переход в другой раздел) равен «Забрать»:
выигрыш получается без анимации, недосмотренная серия подтверждается.
Если ответ открытия, покупки серии или риска пришёл уже после выхода,
клиент повторно получает появившийся выигрыш. Повторные получения безопасны.

Исправление установщика после неудачного прогона 30.10: API-проверки
учитывают отложенное получение серий и однократное зачисление, отсутствие
потолка перевода бонусов и актуальный ответ отчёта Sicilia. RATE_LIMIT_GUESS
повышен только у изолированного тестового сервера, как остальные корзины.

Проверка без применения: `sudo bash /root/luckybox-accounts-start.sh --check`.
Применение после успешной проверки: та же команда без `--check`.
WebKit в серверной проверке запускается с программным рендерингом;
при ошибке сохраняется `test-artifacts/accounts-webkit/trace.zip` в папке
проверки, журнал браузера включён через DEBUG=pw:browser.
Это обход возможного сбоя графического процесса, причину исходного закрытия
страницы подтверждает только повторный прогон и журнал браузера.

Исправление браузерных проверок 30.10.2026: Playwright закреплён на 1.64.1
в package.json и lockfile. В 1.63.0/WebKit 2359 на этом сервере воспроизводился
SIGSEGV ThreadedCompositor (libWPEWebKit, offset 0x60a0f8a); он совпадает
с исправленным upstream https://github.com/microsoft/playwright/issues/42637.
Установщик всегда ставит зависимости проверок через npm ci в отдельную
временную папку, чтобы не использовать старый Playwright рабочего сайта.
WEBKIT_DISABLE_COMPOSITING_MODE удалён: этот параметр не устранял сбой.

Полный UI-прогон также обнаружил обращение к event.currentTarget после await
в обработчике «Продолжить» риск-игры. Ссылка на кнопку сохраняется до запроса
получения выигрыша; регрессия покрыта test/case-exit.mjs и общим UI-сценарием.

Закрытие предпросмотра кейса гостем не отправляет запросы получения выигрыша
и подтверждения серии: у гостя нет выигрышей, а ответ AUTH открывал лишнюю
регистрацию поверх главной. Проверено регрессией и гостевым UI-сценарием.

Safari, 30.10.2026: закрытие риск-стола после подтверждённого получения не
зависит от декоративной анимации. Обработчик закрывает карты и сбрасывает
прокрутку после ответа сервера, повторного запроса получения при возврате к
кейсу нет. Отсутствие кадров или ошибка Web Animations завершают эффект
за ограниченное время; повторное нажатие ускоряет его без второго получения.
Регрессии: test/case-exit.mjs и test/risk-collect-ui.mjs (Chromium/WebKit с
обычными анимациями: отказ до карты, продолжение после карты, ошибка эффекта).
Входной модуль получил новый URL accounts-safari-20261030. Подсказки free-кейса,
первого пополнения и правила бонусов приведены к отдельным выбранным счетам.

Одно получение фриспинов, 30.10.2026: кнопка в итогах серии получает выигрыш
и возвращает к исходному экрану кейса без второго общего итога с «Забрать».
Это относится к покупке пачки и к выпавшим сериям. Подтверждение досмотренной
серии завершается до возвращения к кейсу, чтобы она не запускалась повторно.
Старый ответ покупки больше не подставляется поверх баланса после получения.
Браузерная регрессия: node test/freespin-collect-ui.mjs <адрес тестового сервера>.
