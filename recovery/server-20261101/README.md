# Снимок сервера LuckyBox — 1 ноября 2026

Рабочие исходники и статические файлы находятся в обычных каталогах репозитория.
Они побайтно сверены с `/srv/luckybox`: 2 882 файла. Исходные `assets-src`,
которых уже нет на рабочем сервере, сохранены из предыдущего коммита.

Зашифрованная копия в этом каталоге содержит согласованный снимок `data/app.db`
(проверка SQLite `integrity_check = ok`), весь остальной каталог данных, `.env`
и его прежние версии, настройки Nginx/systemd, сертификаты, рабочие каталоги,
архивы, скриншоты, скрипты и отчёты LuckyBox из `/root`, а также локальные
коммиты, ещё не попавшие в прежнюю удалённую ветку. Снимок базы сделан
2026-11-01 около 23:15 UTC; подробности — `snapshot-info.json`.

Не включены переустанавливаемые `node_modules`, кеши, каталоги `.git`,
файлы самой ОС и инструменты агентов. История Git находится в GitHub и в
`local-history.bundle` внутри зашифрованной копии. Живая SQLite WAL заменена
согласованным снимком штатного SQLite backup API; сервисы не останавливались.

Это разовый снимок. Более поздние изменения и операции пользователей требуют
новой резервной копии. Действующий сервер этим коммитом не перенастраивается.

## Ключ

Ключ — отдельный файл `casssss-recovery-key-20261101.txt` с 64 шестнадцатеричными
символами. Он передан владельцу отдельно и **не хранится в GitHub**.
Скачайте его и сохраните вне исходного сервера, например в менеджере паролей.
Без этого ключа нельзя вернуть базу, секреты и закрытые рабочие материалы.
Шифрование: AES-256-GCM с аутентификацией заголовка и случайным nonce.

## Проверка и распаковка

Понадобятся Node.js 20+, Python 3, GNU gzip, GNU tar и zstd с поддержкой
длинного окна (512 МБ памяти на декодирование). Все действия ниже выполняют
в отдельном каталоге восстановления, не поверх работающего сервера.

```bash
# После git clone репозитория:
cd casssss
sha256sum -c recovery/server-20261101/SHA256SUMS
cat recovery/server-20261101/private.tar.zst.enc.part-* > /tmp/luckybox-private.enc
node recovery/server-20261101/crypt.mjs decrypt \
  /tmp/luckybox-private.enc /tmp/luckybox-private.tar.zst \
  /путь/к/casssss-recovery-key-20261101.txt
mkdir -m 700 /tmp/luckybox-restored
zstd -d --long=29 -c /tmp/luckybox-private.tar.zst \
  | tar -xpf - -C /tmp/luckybox-restored
python3 recovery/server-20261101/unpack-archives.py /tmp/luckybox-restored
```

Большие старые `source.tar.gz` хранятся в распакованном виде, чтобы сжатие
не сохраняло одни и те же исходники многократно. `PACKING.json` внутри копии
содержит оригинальные пути и SHA-256; скрипт возвращает исходные gzip-файлы.
Их побайтное восстановление проверено перед загрузкой. Не удаляйте
`000-repacked-archives`, пока восстановление и проверка не закончились.
Остальные файлы находятся по исходным путям относительно корня сервера.

## Восстановление проекта на новой машине

1. Разверните исходники этого коммита в `/srv/luckybox` и установите Node.js,
   Nginx, системные зависимости сборки `better-sqlite3` и пользователя `luckybox`.
   Ориентируйтесь на `deploy/README.md` и `deploy/install.sh`; установочные
   скрипты могут создавать новую конфигурацию, поэтому проверьте их перед
   запуском с уже восстановленными секретами.
2. Пока приложение и бот остановлены, верните `.env` и `data/` из
   `/tmp/luckybox-restored/srv/luckybox/`. Не переносите старые живые
   `app.db-wal`/`app.db-shm` поверх восстановленной базы; снимок `app.db`
   самодостаточен. Выдайте владельцу `luckybox` доступ к проекту и данным,
   а `.env` — права `600`. Исходный `.running` в снимок не включён.
3. Выполните `npm ci --omit=dev` в `/srv/luckybox`. Готовые файлы сайта уже
   сохранены; для пересборки нужны также зависимости разработки.
4. Проверьте целостность восстановленной базы до запуска:
   `node --input-type=module -e 'import D from "better-sqlite3"; const d=new D("data/app.db",{readonly:true}); console.log(d.pragma("integrity_check",{simple:true})); d.close()'`.
5. Верните нужные службы из `etc/systemd/system/` копии; проверьте пути,
   настройки Nginx и домен. Сертификаты находятся в `etc/letsencrypt/`;
   для другого домена выпустите новые. Выполните `nginx -t`, затем
   `systemctl daemon-reload` и включите службы приложения и бота.
6. Проверьте сайт, вход, данные и доступ бота; при смене машины обновите DNS
   и зависящие от IP настройки внешних интеграций. Таймер прежнего backup
   сам по себе сохраняет только локальные копии, если не настроен внешний
   `RCLONE_REMOTE`; этот снимок не включает автоматическую отправку в GitHub.

Для возврата локальной истории используйте `git bundle verify` и затем
`git fetch /tmp/luckybox-restored/local-history.bundle` из клона этого
репозитория. Bundle опирается на коммит `50308762fe6bf81e79c5e43deb1d07dbc5c00f3c`,
который доступен в истории GitHub. Рабочее дерево проекта этим действием
не переключается автоматически.

Перед удалением старого сервера обязательно сохраните ключ вне сервера и
проверьте распаковку копии на другой машине. Проверка этого снимка не является
проверкой запуска всех внешних интеграций на новом сервере.
